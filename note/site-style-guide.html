冬夢のレトロゲーム攻略メモ 表記・運用ルール

最終更新日：2026/08/27

このページは、GitHub Pages版「冬夢のレトロゲーム攻略メモ」で記事を作成・移行・更新するときの基準書です。新しいページを作るときは、まず「公開前チェックリスト」を確認し、必要に応じて各項目の詳しいルールを参照します。

このページの扱い

  • サイト制作の内部ルール集として使用する。
  • 検索結果に出さないため、noindex, nofollowを設定する。
  • 通常の記事ページからはリンクしない。
  • sitemap.xmlには追加しない。
  • このページ自体にはGoogle AnalyticsとGoogle AdSenseを設置しなくてよい。

公開前チェックリスト

  • <title>とmeta descriptionがページ内容に合っているか。
  • canonicalが、独自ドメイン上の正規URLを絶対URLで指定しているか。
  • Google Analytics（測定ID：G-68L45S7GXM）がhead内にあるか。
  • Google AdSense（パブリッシャーID：ca-pub-7684661108374221）がhead内に1回だけあるか。
  • サイト内リンクと画像パスが相対リンクになっているか。
  • トップページや作品別攻略目次へ戻るリンクが正しいか。
  • 画像に内容の分かるaltが付いているか。
  • 画像を掲載する公開ページで、ページ階層に合った相対パスのlightbox.jsを読み込んでいるか。
  • 記事下部に【作品について】と日付があるか。
  • 本文の日付がYYYY/MM/DD形式になっているか。
  • 公開ページに不要なnoindexが残っていないか。
  • 新規記事や更新記事が作品別攻略目次などからたどれるか。
  • sitemap.xmlへの追加・lastmod更新が必要か。
  • 連続記事では、一覧・前後記事からのリンクが正しいか。

最重要の表記ルール

  • 攻略記事タイトルには、原則として【ゲーム攻略】を付けない。
  • 修理・メンテナンス記事は、必要に応じて【修理記録】を付けてもよい。
  • 作品の権利表記は「出典」ではなく【作品について】を使う。
  • 本文の最終更新日はYYYY/MM/DD形式にする。
  • sitemap.xmlのlastmodはYYYY-MM-DD形式にする。
  • 独自ドメインへの移行に備え、サイト内リンクは原則として相対リンクにする。
  • Blogger版から移行するときは、Blogger側のリンクをGitHub Pages用の相対リンクへ置き換える。

ページ種類ごとの必須項目

攻略記事・攻略データ

  • 記事内容が分かるタイトルとmeta description
  • Google AnalyticsとGoogle AdSense
  • トップページ・作品別攻略目次へ戻るリンク
  • 必要に応じた見出し、表、画像、攻略マップ
  • 【作品について】
  • 最終更新日
  • 作品別攻略目次からのリンク
  • sitemap.xmlの追加または更新

攻略目次・プレイ日記一覧

  • 作品名とページの役割が分かるタイトル・説明文
  • Google AnalyticsとGoogle AdSense
  • 掲載済み記事へのリンク
  • トップページへ戻るリンク
  • 【作品について】
  • ページ作成日または最終更新日
  • sitemap.xmlの追加または更新

修理・メンテナンス記録

  • 必要に応じてタイトルに【修理記録】を付ける。
  • 使用した道具や作業内容、注意点を実際の作業に基づいて記載する。
  • 写真は作業箇所が分かるaltとfigcaptionを付ける。
  • Google AnalyticsとGoogle AdSense、戻るリンク、【作品について】、最終更新日、sitemap.xmlを確認する。

サイト案内・内部ページ

  • トップページへ戻るリンクを付ける。
  • 検索から来る必要が薄いページは、目的に応じてnoindexを設定する。
  • 内部運用メモは通常ページからリンクせず、sitemap.xmlにも載せない。

基本HTML構成

作品フォルダ内の一般的な記事では、次の要素を基本とする。

<!doctype html>
<html lang="ja">
<head>
  <!-- Google Analytics -->
  <!-- Google AdSense -->
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>記事タイトル｜冬夢のレトロゲーム攻略メモ</title>
  <meta name="description" content="記事内容が分かる短い説明文。">
  <link rel="canonical" href="https://little-winter-dream.com/フォルダ名/ファイル名.html">
  <link rel="stylesheet" href="../style.css">
</head>
<body>
  <header>
    <h1>記事タイトル</h1>
    <p>
      <a href="../index.html">トップページへ戻る</a> /
      <a href="index.html">攻略目次へ戻る</a>
    </p>
  </header>

  <main>
    <!-- 本文 -->

    <p><a href="index.html">→ 攻略目次へ戻る</a></p>

    <hr>
    <div class="note">
      <p>
        <strong>【作品について】</strong><br>
        本ページで扱う作品名・各種権利は、各権利者に帰属します。<br>
        『作品名』（機種名）<br>
        ©権利表記
      </p>
      <p>最終更新日：YYYY/MM/DD</p>
    </div>
  </main>
</body>
</html>

Google Analytics

攻略記事、修理記録、作品別目次、基本情報、感想ページなど、閲覧数を確認したい公開HTMLページでは、次のコードをhead内へ追加する。 

<!-- Google tag (gtag.js) -->
<script async src="https://www.googletagmanager.com/gtag/js?id=G-68L45S7GXM"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('js', new Date());

  gtag('config', 'G-68L45S7GXM');
</script>

独自ドメインへ切り替えた場合は、Google AnalyticsのGA4データストリームURLも新しいドメインへ変更する。

Google AdSense

AdSenseの審査・広告配信に使う公開HTMLページでは、次のコードをhead内へ1回だけ追加する。 

<script async src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-7684661108374221"
     crossorigin="anonymous"></script>
  • 新しい公開ページを作るときは、Google Analyticsと一緒に追加する。
  • 既存の公開ページを複製して作る場合も、コードが1回だけ含まれていることを確認する。
  • 同じページへ重複して追加しない。
  • 内部運用メモなど、広告対象にしないページには追加しない。
  • コードを追加しただけで、審査前から広告が表示されるわけではない。

タイトルとmeta description

<title>には記事タイトルとサイト名を入れる。区切り記号は、同じ作品・同じ種類の既存ページに合わせる。

攻略記事の例：

『魔法陣グルグル』（SFC）ストーリー攻略 前半｜オープニング～聖なる塔

修理記事の例：

【修理記録】ワンダースワンの偏光板を交換してみた

プレイ感想記事の例：

『魔法陣グルグル』（SFC）プレイ感想｜遊んでみた感想まとめ

meta descriptionは、検索結果に表示されても自然で、ページ内容が分かる短い説明にする。 

<meta name="description" content="スーパーファミコン版『魔法陣グルグル』のストーリー攻略前半です。オープニングから聖なる塔までの出現モンスター、宝箱、攻略メモをまとめています。">

canonical（正規URL）

検索エンジンへ正規URLを明示するため、公開HTMLページではhead内へcanonicalを1回だけ追加する。 

<link rel="canonical" href="https://little-winter-dream.com/フォルダ名/ファイル名.html">
  • サイト内リンクとは異なり、https://little-winter-dream.com/から始まる絶対URLを使用する。
  • 通常の記事ページは、独自ドメイン上の表示URLをそのまま指定する。
  • index.htmlは、原則としてファイル名を省略した末尾/のURLを正規URLにする。
  • 旧GitHub Pagesや旧BloggerのURLは指定しない。
  • 同じページへ複数のcanonicalを追加しない。

ファイル名

英小文字とハイフン区切りを基本にし、内容が分かる名前にする。

story-walkthrough-01.html
item-equipment-list.html
play-impressions.html

リンク

サイト内リンクは原則として相対リンクを使用する。

<a href="../index.html">トップページへ戻る</a>
<a href="index.html">攻略目次へ戻る</a>
  • 作品フォルダ内の記事は、作品別攻略目次へ戻れるようにする。
  • 連続記事は、一覧ページまたは前後記事からたどれるようにする。
  • 新規記事を公開したら、作品別攻略目次など必要な一覧ページへリンクを追加する。

【作品について】と日付

記事下部の権利表記には「出典」ではなく【作品について】を使う。

<hr>
<div class="note">
  <p>
    <strong>【作品について】</strong><br>
    本ページで扱う作品名・各種権利は、各権利者に帰属します。<br>
    『作品名』（機種名）<br>
    ©権利表記
  </p>
  <p>最終更新日：YYYY/MM/DD</p>
</div>

本文の日付：

最終更新日：2026/08/09

sitemap.xmlの日付：

<lastmod>2026-08-09</lastmod>

攻略マップ清書ルール

  • 白背景を使い、壁と通路は黒線で作成する。
  • 左側に黒枠の【メモ】欄を設け、【メモ】の見出しは中央揃えにする。
  • 赤い普通の数字（1・2・3）はアイテムに使う。
  • 青い英大文字（A・B・C）は階段・マップ間移動・ワープなどの移動地点に使う。
  • 対応する移動地点には同じ英字を使う。上り・下り・移動先はマップ上へ詰め込まず、メモ欄へ記載する。
  • 青英字には原則として個別メモを付ける。同じ英字が複数ある場合、【移動】欄の説明は1行にまとめてよい。
  • 赤い丸数字（①・②・③）は敵・イベント・重要地点などに使い、内容に合う見出しを付ける。
  • 黒い英小文字（a・b・c）は部屋名や部屋の識別に使う。
  • 赤数字のメモには【アイテム】、青英字のメモには【移動】の見出しを付ける。
  • ドアなどの移動要素は青系を基本とし、必要に応じて薄青色で表現する。
  • 旧仕様の赤い☆と青い△・▽は、新しいマップでは使用しない。
  • 手書きマップの通路構造と記号の位置関係を優先し、不明な場所を勝手に補完しすぎない。
  • マップ本体の見やすさを最優先し、メモ文字も読める大きさを確保する。
  • 説明が長い場合は画像内へ詰め込まず、記事本文側で補足する。
  • 必要に応じてマップを少し縮小し、左側のメモ欄を下方向へ広げてもよい。

攻略マップについての表記

攻略マップを掲載する作品では、作品別攻略目次などの自然な位置へ次の文章を入れる。

※当サイトの攻略マップは、実機プレイによる調査をもとに独自に作図したものです。

各マップ画像へ毎回繰り返す必要はない。トップページと「このサイトについて」にも、サイトの特徴・運営方針として記載する。現在はWizap!攻略目次にも掲載し、サバイバルキッズ2の既存ページはこの理由だけでは変更しない。

画像

本文画像にはfigureとfigcaptionを使い、altには画像が表示されなくても内容が分かる説明を入れる。

<figure>
  <img src="../images/フォルダ名/画像ファイル名.JPG" alt="画像の内容を表す説明">
  <figcaption>画像の補足説明。</figcaption>
</figure>

画像を掲載する公開ページでは、</body>の直前に、ページ階層に合った相対パスで共通のライトボックス用JavaScriptを読み込む。 

<script src="../lightbox.js" defer></script>

2階層下のページでは../../lightbox.jsのように調整する。同じページへ重複して追加しない。

表・補足・折りたたみ

  • 補足や注意書きには.noteを使う。
  • 表は.table-wrapで囲み、スマートフォンで横スクロールできるようにする。
  • 基本情報には.info-table、魔法・アイテム・装備品一覧などには.guruguru-table、敵一覧には.enemy-tableを必要に応じて使う。
  • 長い一覧や補足情報にはdetailsを使ってよい。
  • ストーリー攻略の主要部分やプレイ感想では、折りたたみを使いすぎない。
<div class="table-wrap">
  <table class="info-table">
    <!-- 表の内容 -->
  </table>
</div>

noindex

  • 通常の攻略記事、修理記事、目次、プレイ感想には原則としてnoindexを付けない。
  • 検索から来る必要が薄い案内ページでは、必要に応じてnoindex, followを検討する。
  • 検索にもリンク巡回にも出したくない内部運用メモではnoindex, nofollowを使う。
  • 仮ページにnoindexを付けた場合は、正式公開時の外し忘れに注意する。

sitemap.xml

新しい公開ページを追加した場合は、次の形式でsitemap.xmlへ追加する。既存ページを更新した場合は、必要に応じてlastmodを更新する。

<url>
  <loc>https://little-winter-dream.com/フォルダ名/ファイル名.html</loc>
  <lastmod>YYYY-MM-DD</lastmod>
</url>

内部運用メモや、このsite-style-guide.htmlは追加しない。

移行・文章作成の方針

  • データ収集と本文の土台は、実際のプレイや作業記録に基づいて作る。
  • Blogger版をそのまま複製せず、GitHub Pages版では見出し・表・リンクを読みやすく整理する。
  • プレイ感想やプレイ日記は、元の文章の雰囲気を残し、過度に固く整えすぎない。
  • 読者が情報を探しやすいよう、見出し数と項目数を必要以上に増やさない。
  • 不明な情報や未確認の効果を、推測だけで確定事項として書かない。
個人的なメモ

まず前提として、データ収集や本文作成は自分の手でプレイして集めたり書いたうえで、文章の読みやすさやHTMLコードなど複雑な点を補助するためにAIの助けを借りることが重要です。

私にとってこのブログの目的、重要な点はレトロゲームをプレイする人の助けになれる事です。

今の時代、説明書無しのソフト単体で販売されている場合が多いです。プレイする時必要な情報がこのサイトから得られるように、攻略に行き詰まった時に、私が得た知識の一部でも役に立てば助かる人がいるかもしれません。

西暦1998年頃にあった昔の個人攻略サイトなどは失われつつあるでしょう。あの人たちが作り上げたレベルとはいかなくても、私が不完全でも新しく発信していけば未来に繋がる物もあるかもしれません。

小さくても、未熟でも構いません。何年後にも何十年後にもなるかもしれませんが、あなたが作り上げた物が誰かの助けになるかもしれません。

見知らぬ誰かが作った攻略サイトに助けられた事を忘れないで、今度はあなたがその見知らぬ誰かになれたなら……きっとそれが私の、あなたの人生を使ってでも成し遂げるモノのひとつに成り得るでしょう。
